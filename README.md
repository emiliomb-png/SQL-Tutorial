# Do Rich Parents Have Rich Kids? Matching Parents and Children in the PSID with SQL and Python

A class tutorial showing how to use SQL inside Python (SQLite + pandas) to link parents and children in the Panel Study of Income Dynamics (PSID), build parental and child income measures, and estimate the intergenerational elasticity (IGE) of income.

## What the project does

1. **Builds the parent-child match** from PSID individual and family identifiers, using `SELECT`, `NULLIF`, self-`JOIN`s (`LEFT JOIN`), `GROUP BY` / `HAVING` for validation, and aggregation (`SUM`, `COUNT`, `AVG`).
2. **Constructs income measures** for both generations: reshapes the wide individual file to person-year (`UNION ALL`), joins on wave and family number, deflates to 2016 dollars, and uses a window function (`ROW_NUMBER() OVER ...`) to pick a single-year snapshot versus a multi-year average.
3. **Estimates the IGE**: the slope from regressing ln(child income) on ln(parent income).
4. **Compares single-year and multi-year income**, and shows life-cycle bias by estimating the IGE separately at each child age.

## Results (N = 3,115 children)

| Parent income | Child: single year | Child: multi-year |
|---|---|---|
| Single year | 0.410 | 0.386 |
| Multi-year | 0.494 | 0.462 |

| Child age | 25 | 30 | 35 | 40 | 45 |
|---|---|---|---|---|---|
| IGE | 0.428 | 0.419 | 0.512 | 0.452 | 0.550 |
| Mean income | $61,427 | $70,254 | $84,253 | $90,567 | $98,179 |

- Replacing a one-year parental snapshot with a multi-year average raises the IGE by about 0.08. This is consistent with attenuation bias from transitory income noise.
- Estimates from young children (25-30) are lower than those from older ones, which is consistent with life-cycle bias (Solon 1992; Haider and Solon 2006). The age-40 dip is within noise, and each age mixes different cohorts, so read the pattern as indicative.

## Key design choices

| Choice | Setting |
|---|---|
| Person key | `ER30001*1000 + ER30002` (1968 family ID x 1000 + person number) |
| Parent measurement window | Child aged 15-19, centered on 17, at least 2 observed years |
| Child measurement window | Age 30-40, centered on 35, at least 3 observed years |
| Income floor | $1,000 (drops values that cannot be logged) |
| Base year for prices | 2016 dollars (CPI annual averages, 1983-2016) |
| Single-year measure | Observed year closest to the center age |
| Multi-year measure | Average of observed years in the window |

Notes on the data: family income refers to the previous calendar year (interview year - 1); pre-1994 income variables bottom-code zero and negative values at $1; family IDs change every wave, so the 1968 ID is the only stable anchor.

## Data

PSID data cannot be redistributed, so no data files are included in this repo. Download them (free registration) from the PSID Data Center: https://simba.isr.umich.edu/

You need:

- **Cross-year Individual file** (`IND2023ER`): fixed-width `.txt` plus the Stata `.do` file, which the code uses to read the column positions.
- **Parent Identification file** (`PID23`): `.txt` plus `.do`.
- **Family files, 1984-2017** (24 waves: 1984-1997, 1999, 2001-2017). Only the `.txt` and `.do` files from each ZIP are needed; keep them anywhere inside one folder (the script finds each `famYYYY` file automatically).

## How to run

Edit the settings at the top of `SQL_tutorial.py`, then run the whole script (not line by line).

1. **Set the paths.** `IND_TXT`, `IND_DO`, `PID_TXT`, `PID_DO` (Part I), and `CHILD_PARENT_CSV`, `FAM_DIR` (Part II). Part I writes `child_parent_pairs.csv` to your working directory; point `CHILD_PARENT_CSV` at that file.
2. **Check the CPI.** The `CPI` dictionary holds CPI-U annual averages for 1983-2016, with `BASE_YEAR = 2016`. If it is empty, the script warns and uses nominal dollars.
3. **Run it.** Part I builds and saves the match. Part II loads it, builds the income measures, and prints the match rates, the IGE tables, and two Markdown versions of the results tables.

Part I has an `EXTRA` dictionary (empty by default) for pulling additional individual-file variables into the match, for example `EXTRA = {"sex": "ER32000"}`.

## Validation checks

The script prints or computes these so you can confirm the pipeline is sound:

- A `GROUP BY ... HAVING COUNT(*) > 1` query on the match table (`dupes`) should return zero rows: each child appears once.
- Match rates (children with a known mother and father, and parents found in the PSID) via `SUM(... IS NOT NULL)`.
- "Person-waves with no family record" should print about 0.
- The sample size is the same in every cell of the IGE table.

## Limitations

- Standard errors are plain OLS. Siblings share the same parental income, so clustered standard errors would be larger.
- Age windows and the income floor are design choices so results will move if you change them.
- Each child age in the life-cycle table mixes different birth cohorts.

## Output

The script prints the results tables to the console, including Markdown versions of Table 1 (single vs multi-year) and Table 2 (IGE by child age).
